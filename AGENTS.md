# AI Agent Handoff: Gnomish Positioning System (GPS)

GPS is a World of Warcraft addon for **WoW Forever** that replaces the cartoon world map with a zoomable top-down map built from the game's own minimap images. A 3D (perspective) mode is being prototyped separately, and Blizzard's own map ("the traditional map") is the third mode, the one that opens where GPS cannot show you. The design, measurements and decisions are in `INTEGRATION_PLAN.md`; read it before changing anything.

## Layout

- `Interface/AddOns/GnomishPositioningSystem/`: the addon (about 3 MB).
  - `Debug.lua` (since 2026-10-17, loaded first): the debug log, `/gps debug on|off|clear|show|mark <note>` and a switch on the settings page. Off by default, and then `ns.Log(category, format, ...)` returns at once (measured: no change in 2D or 3D frame times). On, lines (`HH:MM:SS  GetTime  CATEGORY  text`) go to the saved variable `GnomishPositioningSystemLog` (`{ on, lines, bytes }`), which the game writes on `/reload`, logout or quitting to `WTF\Account\<account>\SavedVariables\GnomishPositioningSystem.lua`: the file to hand over (addons cannot write other files). Size: at most 1,000,000 bytes of text (about 10,000 lines); past that the oldest lines are dropped to 800,000 bytes, with a note; one line at most 400 characters; at each login with the log on, a chat reminder says so. Categories: COMPAT (other addons' map layers found, copied, left alone, switched off, removed; GatherMate2's node list), MODELS (GPS3D's game models: the building check's answer, models that never load), SESSION (header at login/reload and when turned on: build, versions, screen and scale, data and APIs, quests and zones known, both settings tables, your position), SLASH, MODE, WINDOW, VIEW (each window's view when it changes; the 3D one from `GPS3D_API.DebugState`), MAP, MAPWIN, QUEST, SETTING, POS (your position when you move more than 2 yd or turn, else every 10 s; checked every second), PERF (2D layout times, 3D frame times from `GPS3D_API.TakePerf`, game fps; every 5 s), MEMORY (every 30 s), EVENT (loading screens, zones, combat, UI scale, logout), TAINT (`ADDON_ACTION_BLOCKED` / `FORBIDDEN`), ERROR (every Lua error whose text or stack mentions GPS's files, one line per line of message and stack; the hook is `seterrorhandler`, installed only while on and given back when turned off, and the game's own handler still runs), MARK (your notes), TEST (the self-test lines). GPS3D logs through `GPS_API.Log` (camera mode, straight down, view map, Me failures, slash commands, self-test). `/gps debug show` opens the newest 1,500 lines in a window to copy (Ctrl+A, Ctrl+C).
  - `Core.lua`: the 2D map. Standalone frame (`/gps`, key binding in `Bindings.xml`), left-drag pans, the wheel zooms around the cursor, the Me ring centres on the player and follows, `<` `>` switch maps (brass, a size up from the map's name since 2026-10-18; they save that you stopped following, as a drag does, so a reload keeps the browsed map; the 3D view has them too). Modes (since 2026-10-17): the 2D map, the 3D view (GPS3D) and the traditional map (`MapWindow.lua`), one window at a time at the same place and size. `ns.modes[name]` says how to open each (`Frame`, `open(from, focus)`, `focus()`, `available()`); the mode ring (`ui.modeSwitch`, labelled `2D` / `3D` or a folded-map icon) steps 2D -> 3D -> Map -> 2D, right-click steps back (`ns.StepMode`), and the mode picked is remembered (`db.mode`). `GPS_Toggle` (the key binding, `/gps`) closes whichever window is open, or opens `ns.DefaultMode()`: the remembered mode, except the traditional map where GPS cannot show you (`ns.PlayerOnGPSMap()` false: no `UnitPosition`, or a map GPS has no data for). `ns.CheckAutoMode` (PLAYER_ENTERING_WORLD, ZONE_CHANGED_NEW_AREA, and again 1 s later) switches a 2D or 3D window that is showing you to the traditional map when that changes to false, and back when it changes to true if the switch was automatic (`ns.autoMap`); a mode picked by hand stays until the next such change. Focus passed between modes: `{ map, gx, gy }`, `"you"` (the window left was showing you: follow you), or nil (open as last time). `/gps 2d`, `/gps 3d`, `/gps map` open a mode by name (`ns.OpenNamed`; GPS3D's `/gps3d` commands use it too, through `GPS3D_API.Open`, so only one window is ever open). Every window's move or resize is saved as the one place and size (the 3D window too, since 2026-10-17). The title is the zone in the middle of the view (`ns.ZoneNameAt(map, gx, gy)`: the game's map there through `C_Map.GetMapPosFromWorldPos`, a dungeon or micro map's zone above it, cached per eighth of a tile; nil over the sea or between zones, then the map's name), the subtitle the map's name, the footer where you are; the 3D view's title does the same for the point it looks at (`GPS_API.ZoneNameAt`; since 2026-10-17, before that both showed your zone). The 2D map reads your position every frame (title and footer every 0.2 s) and, while following you, moves to the map you are on when you change continent. The look is "minimap rings" (option B of the 2026-10-16 look study, the "GPS look options" design canvas): frameless with a 1 px black edge, title and map switch at the top left, Blizzard's red close button (`RedButton-Exit` atlases), a column of round buttons in the minimap's gold ring down the right edge (`MiniMap-TrackingBorder` over `UI-Minimap-Background`; the art's ring is centred at texel 20.0 across and 19.0 down, so it is cropped from 0.5 to 39.5 across, which centres it on the button, and 0 to 39 down, the disc, label and icon placed `centreY`, half a texel, above the middle; until 2026-10-18 the crop started at 0 across and everything in the rings sat 0.4 px left of the ring; `UI-Minimap-ZoomButton-Highlight` on hover; labels and icons brass at rest, gold when active), two rings like the others with a small `+` / `-` (9 px) drawn from `WHITE8X8` bars at the bottom right (until 2026-10-17 the minimap's `ui-hud-minimap-zoom-*` atlases, whose sign was too big), and where you are at the bottom left; the mouse controls are in the rings' tooltips. Built by `ns.ApplyChrome` (`ui.SetRings(list)` lays out the column; every window starts it with the same three rings, compass, mode and Me, at the same places, so they stay under the mouse when switching modes; in the 2D map and the traditional map, which are always north-up, the compass needle just points up) and shared with GPS3D through the global `GPS_API` (`Usable`, the secret-value check; `PlacePin` / `HidePins`, the marker pools of quests and other addons' nodes in both views, which hide only the markers shown last time; `MapOrder`; `ApplyChrome`, `RingButton`, `TextButton`, `CopyGeometry`, `colors`, `MEDIA`, `WhereText`, `Show`, `StepMode`, `OpenMode`, `OpenNamed`, `SaveGeometry`, `PlayerPosition`). Debugging: `/gps test` (self-test report), `/gps grid` (tile numbers, on the 2D map: turned on from the 3D view or the traditional map it switches that window to the 2D map at the same place, the chosen mode kept; turned off it opens nothing; until 2026-10-18 it showed the 2D map over the 3D view), `/gps where`, `/gps swapaxes` and `/gps flipfacing` (toggles if the self-test finds the position axes or facing reversed).

Built on first use the way Blizzard builds its zone map (`Blizzard_BattlefieldMap`): a frame mixed with `MapCanvasMixin`, a `MapCanvasFrameScrollContainerTemplate` scroll frame and an empty `BorderFrame` made before `OnLoad` (Blizzard's `OnLoad` reaches into both), the zone map's data providers plus `AreaLabelDataProviderMixin` (hovered zone name, offset -58 under the title band) and, since 2026-10-17, the quest layers of Blizzard's world map (`QuestOfferDataProviderMixin`, `BonusObjectiveDataProviderMixin`, `QuestBlobDataProviderMixin`, `QuestDataProviderMixin`, `WaypointLocationDataProviderMixin`, `SuperTrackWaypointDataProviderMixin`: quest givers, bonus objectives, the tracked or hovered quest's area, your quests' buttons, your map pin, the tracked quest's waypoint), 27 providers in the world map's order, a missing one skipped; pin frame levels as Blizzard's world map defines them (`PIN_LEVELS`, in `Blizzard_WorldMap.lua`'s order; the quest-offer and active-quest ranges read when the map is made); Blizzard's own `WorldMapFrame` is never touched. Blizzard's mouse controls (click a zone to open it, right-click for the map above, wheel zoom, drag pans when zoomed); rings: mode, Me (your map; gold while showing it); the zoom rings call `ZoomIn`/`ZoomOut`; `<` `>` change floor on maps with several (`C_Map.GetMapGroupMembersInfo`), else the subtitle is the parent map. The map follows you between zones and floors while it shows yours. Focus to and from the other modes through `C_Map.GetMapPosFromWorldPos` / `GetWorldPosFromMapPos`. Its window keeps its place and size as the saved one (`ns.SaveGeometry`). `/gps test` adds a `traditional map:` line (`ns.MapSelfTest`).
  - `Quests.lua` (since 2026-10-17): your quests on the 2D map and in the 3D view. `ns.quests.List(instance)`: every quest the game gives a point on a zone of that GPS map (`C_QuestLog.GetQuestsOnMap` for each zone: the uiMap at a point on land, up to its continent, then its zones on that instance, cached), converted with `C_Map.GetWorldPosFromMapPos` (the traditional map's conversion; not affected by `/gps swapaxes`), the tracked quest (`C_SuperTrack`) last; rebuilt 0.25 s after quest, tracking, watch or `questPOI` events. Markers are Blizzard's quest button (`POIButtonTemplate`, styled as `QuestDataProviderMixin.AddQuest` does: number or `?`, selected when tracked; its click tracks the quest), with GPS's tooltip (title, objectives left, what a click does); a plain `QuestNormal` button where the template is missing. In 2D they sit on a layer at canvas level + 8 (under your arrow, + 10) and are placed by `ns.LayoutQuests` from `ns.Layout`. Objective areas (2D): the tracked quest's and the hovered marker's, each drawn by a `QuestPOIFrame` (the game's own quest-area frame, the one Blizzard's map uses; Blizzard's fill and border textures and alphas) set to the quest's zone and anchored to that zone's rectangle on the 2D map (its corners (0, 0) and (1, 1) through `GetWorldPosFromMapPos`), drawn again after a size change; one frame per zone, level + 5. Shown when the setting is on (`db.quests`, default on) and Blizzard's `questPOI` option is on. Shared with GPS3D through `GPS_API.QuestList`, `QuestStamp`, `NewQuestPin`, `SetupQuestPin`; GPS calls `GPS3D_API.QuestsChanged` when they change. `/gps test` adds the `quests:` lines, the in-game check of what the source cannot answer (TESTING.md section 9).
  - `Compat.lua` (since 2026-10-17): other addons' map markers in GPS's windows, without copying any of their code (GPS calls what they expose at run time while they are installed). (1) Map layers: `hooksecurefunc` on `WorldMapFrame:AddDataProvider` / `RemoveDataProvider` (only watching; Blizzard's map is not changed) plus a scan of `WorldMapFrame.dataProviders` at login and when the traditional map is made (`ns.compat.MapMade`, from `MapWindow.lua`'s `mw.Make`): every layer an addon added (GatherMate2, HandyNotes and its plugins, RareScanner if it adds its own the same way) is copied onto the traditional map (Blizzard's canvas code), so the addon's own code draws its pins there with its templates, tooltips and clicks. Who made a layer: `issecurevariable` on its function fields (Blizzard's are secure, an addon's tainted with its name); without that API, the layers on Blizzard's map when GPS loaded count as Blizzard's. Left alone: Blizzard's own layers and pin-library layers (`LibStub` libraries with that `worldmapProvider`, HereBeDragons-Pins: TomTom, Questie), whose icons are frames the addon owns. A copy is the provider's fields without `owningMap`, `registeredEvents` and frames, with its metatable; its lifecycle methods (`OnAdded`, `RefreshAllData`, `OnMapChanged`, `OnEvent`, canvas callbacks ...) run under `pcall`, and an error switches that copy off (`state = "failed"`, the reason in `/gps test` and the debug log) instead of throwing. When the addon calls `RefreshAllData` or a `Refresh*` / `Update*` method on its original, the same call is replayed on the copy while GPS's map shows (post-hooks on the original). Frame levels an addon defined on Blizzard's map are added to the traditional map's. A layer the addon removes leaves the traditional map and comes back if re-added. (2) GatherMate2 on the 2D map and in the 3D view: `LibStub("AceAddon-3.0"):GetAddon("GatherMate2")`, its `GetNodesForZone` (with its own filters), `DecodeLoc`, `GetNameForNode`, `Visible` (after its `Display:UpdateVisibility`), `nodeTextures`, `nodeIDReplacementMap`, `phasing`, its profile's `scale`, `alpha`, `showWorldMap`, `worldMapIconsInteractive`, for every zone of the map shown (`ns.quests.ZonesOn`, positions through `ns.quests.ZoneRect`); the list is rebuilt after its `Display:UpdateWorldMap` or `ScheduleUpdate` (a new node), at once and then at most once a second; bucketed by tile. Pins are made from its `GatherMate2WorldMapPinTemplate` and use its pin mixin's `OnMouseEnter` / `OnMouseLeave` / `OnClick` (tooltip, right-click menu), a plain icon where that is missing. 2D: from 40 px per tile, the nodes in view, at most 800, on a layer at canvas level + 7 (under the quest markers). 3D (`GPS3D.lua`, `ns.UpdateAddonPins` in `Render`, through `GPS_API.AddonNodes` / `NewAddonPin` / `SetupAddonPin`): within 700 yd of the middle of the view while the camera is closer than 2,000 yd, at most 400, on the ground (`GroundHeight`, cached per node), at canvas level + `BUCKET_FRAMES` + 4. Setting *Other addons' map markers* (`db.addonMarkers`, default on). `/gps test` adds two `other addons:` lines; debug log category COMPAT.

Controls are plain tables (`kind` header, check, choice, slider or button, with `key`, `default`, `get`, `set`), so GPS3D describes its own without touching the Settings API; each `set` applies at once, the same as the slash commands. `/gps options` (`settings`, `config`) opens the page (`Settings.OpenToCategory`). Without the Settings API there is no page and nothing fails.

  - `Media/*.tga`: GPS's own icons (compass needle, the camera-mode ring's three icons CamFollow, CamBehind and CamFree, the grid square of the straight-down ring, the folded map of the traditional map's mode ring), 64x64 32-bit TGA, drawn by `scripts/make_media.py`.
  - `Overview/*.jpg`: generated. Zoomed-out images, 64 px per tile, up to 16x16 tiles per atlas. Tiles a map does not have are open sea, #081110 (8, 17, 16), the colour of open sea in the game's minimap images; the 2D map's background (`SEA`, `GPS_API.colors.sea`) and the 3D view's background are the same, so zoomed out the sea runs on past a map's last tiles without a change of colour (until 2026-10-17 the empty tiles and the 2D background were #0f2434 and the 3D background a sky gradient; `scripts/fill_overview_sea.py` repainted the existing images, `browser_export.js` fills new exports with #081110).
- `prototypes/GPS3D/`: the 3D view (`/gps3d`, depends on GPS, saves `GPS3D_DB`).
  - Terrain for the whole game: `Data/World_<map>.lua` (16 maps with outdoor terrain, 2,277 tiles, 4.8 MB; generated by `scripts/build_world.py`): per ADT tile a 33x33 height grid (16.7 yd apart; ground, liquid surface or sea level, whichever is highest), 2 base64 characters per height. Since 2026-10-17 each string ends with 2 more characters, the tile's highest height (`build_world.py`), and heights are read from the strings when needed (`TileHeights` returns `{ s, base, lo, hi }` with the heights behind `__index`): nothing is decoded ahead or kept, where before every tile in view was decoded into a table for its height range and kept (a first zoom-out over a continent cost 90-160 ms in one frame and 20-30 MB that stayed; now about 20 ms and under 3 MB in the sandbox). Tiles around the camera become triangles at a level of detail chosen by distance (cell 16.7 to 533 yd) within a triangle budget (3,200 by default, `/gps3d budget`), edges matched to coarser neighbours (no cracks), tiles outside the view skipped. A tile uses its minimap image (FileDataID from GPS's MapTiles via `GPS_API.Maps`) whenever it is bigger than 80 px on screen at its nearest point (`MINIMAP_PX`), whatever its mesh level of detail; smaller ones use GPS's 64-px overview atlases. (Until 2026-10-14 the choice followed the mesh step, so a busy view with a coarse step showed large blurry patches.) Triangle textures come from a pool; tile meshes are cached for 3 s.
  - Buildings for the whole game: `Data/Detail_*.lua` (15 maps, 859 tiles with WMOs, 9,645 blocks, 46.7 MB in 20 files; generated by `scripts/browser_export_detail.js` (in the browser, or in Node with `scripts/export_detail_node.ts`; `scripts/merge_detail.py` takes a fresh export's changed tiles into `data/detail_*.json`) + `scripts/build_detail.py`). Caves and mines (since 2026-10-17, `scripts/browser_underground.js`: a WMO whose interior groups lie at least 70 % below the ground and whose exterior, the rock shell, at least 15 %; 382 of the 4,218 WMO placements with groups) keep only their exterior groups, the parts the game draws outside (the rock around the entrance, a mine's timber frame); their interior groups (tunnels and rooms) are left out, so no tunnel near the surface raises the ground (`scripts/browser_wmo_groups.js` recovers which vertices belong to which group from the stored group boxes, the triangles and the baked interior light: on the game's caves and mines 148 of 151 WMO models exactly, 34 of 3,966,814 vertices wrong, all exterior ones taken as interior). The 31 with rooms below a building standing on the ground (by their positions: the ruins over the Undercity, Karazhan, crypts, the Deadmines' entrance in Moonbrook) keep every group. The bump at the cave just east of Northshire Valley is its exterior: the entrance's rock canopy, 10 to 20 yd above the valley floor, drawn by the game over a hole in the terrain; the tunnels never reach above the ground there. Leaving caves out whole (the first try, also 2026-10-17) was wrong: with no building left on those tiles the blocks went too, and the ground there fell back to the 16.7-yd grid, up to 44 yd off the game's terrain at that cliff (mean 4.1 yd off within 70 yd, against 2.2 with the blocks). Only tiles with caves differ from the 2026-10-14 export (337 changed, 54 the same, and 4 Ahn'Qiraj tiles whose only raised parts were rooms have no blocks now); the 468 others are unchanged (14 of them come out slightly differently today, wall colours and a few heights: the game files or MapExplorer changed in between). Per tile with buildings, 66.7-yard blocks (8x8 per tile) of a 1-yard height raster (ground, water and every WMO face from above, steep roofs and spires included; highest wins) turned into a mesh by greedy Delaunay refinement (1 yd error near buildings, 4 yd elsewhere), at three levels: fine (`ns.Detail`, every sample), coarse (`ns.DetailLow`, every 4th sample) and far (`ns.DetailFar`, every 8th); the coarser levels take the sample as it is (no max filter, so they stay aligned with the minimap). Only real walls (WMO faces steeper than about 78 degrees) carry a colour, from their texture average; a steep mesh triangle is drawn flat-coloured only when its highest corner is on such a wall, everything else (roofs, spires, ground) shows the minimap. Blocks within 1,000 yd of the view centre are drawn on top of the grid while the camera is closer than 2,500 yd, nearest the centre first, until the budget (4,000 triangles, `/gps3d buildings <n>`, `/gps3d detail on|off`) is used. A block's level is the coarsest whose vertex spacing stays under 10 px on screen (`LEVEL_PX`); a block that does not fit the budget at that level is left flat rather than drawn coarser (that is what made dense quarters such as Stormwind's Mage Quarter look broken up). The grid stays drawn under them (its triangles there are sorted as if 30 yd further away), so seams never show the background. Blocks are decoded when first needed (at most 400 kept, the least recently used quarter dropped past that: a busy frame touches up to about 115; 1,500 until 2026-10-18, up to 80 MB) and at most 1,500 triangles of new blocks are made into textures per frame. Cost measured in the sandbox (native Lua): about 2-4x the grid-only frame in cities at the default budget; +52 MB Lua memory and about 0.2 s parse at login.

Your position comes from GPS (`GPS_API.PlayerPosition`, the same rule as the 2D map, `/gps swapaxes` and `flipfacing` included), read every frame so following is smooth (the footer text 5 times a second). The title band has GPS's `<` `>` around the map's name (since 2026-10-18, `ns.CycleMap`): the previous or next map with terrain in GPS's order (`GPS_API.MapOrder`), its main land seen whole from above, the camera freed. Rings in the 3D window, top to bottom: compass (GPS's `ui.compass`, the needle turned by `SetRotation(rad(yaw))`, click: north up), the mode ring (`3D`; click: traditional map, right-click: back to 2D; GPS3D gives the other modes where it looks through `GPS3D_API.Focus`), Me, camera mode, straight down / tilted (since 2026-10-17 compass, mode and Me come first, at the same places as in the other two windows, so switching modes leaves them under the mouse). Modes Free / Follow / Behind (the camera ring steps Follow -> Behind -> Free -> Follow; Me locks back on in the last lock, which is remembered; the footer ends with the mode): left-drag grabs the ground (switches to Free), right-drag turns and tilts, wheel zooms toward the cursor (Free) or around you, double-click flies there, compass turns north up. Behind keeps yaw = -facing + a right-drag offset, eased. Height (since 2026-10-15): panning keeps the camera's altitude (the orbit height `cam.th` stays; a drag, double-click or mouse-up no longer resets it to the ground under the view), so a mountain comes closer instead of lifting the camera. Only where the ground or a roof comes within `CLEARANCE` = 8 yd of the camera is it lifted (`Lift`, not stored: it drops back once you are past), and zooming in stops at that height (`Zoom` bisects the step). Since 2026-10-16 that clearance is checked over everything within 25 yd (`GroundUnder`: the camera's spot and 4 rings, 49 points), and, tilted, the view line must also clear the ground for `AHEAD` (1.2) x cos(tilt)^2 of the way to the point looked at (`LiftFor`, sampled every 6 yd), so a hill in front lifts the camera over it instead of filling the view (fades out toward straight down, where only the 8 yd count). Both are skipped when the camera is clearly above the highest point of the tiles involved (`TileTop`: grid maximum and the highest building vertex, read from the block strings once per tile). Triangles crossing the near plane are cut 1.5 yd in front of the camera and their front part drawn with 3 or 4 corners and adjusted texture coordinates (`DrawClipped`), instead of being hidden; cut parts wholly off screen are skipped. Before this, a low tilted camera looking into a slope showed sky through the ground. In Free mode a zoom keeps the height it ends at as your altitude. Grab and zoom use the real ground point under the cursor (`ScreenToTerrain`, a ray march), so it stays under the cursor whatever the altitude. Follow and Behind still orbit you at your height.
  - Your quests (since 2026-10-17): the markers of GPS's `Quests.lua` (`GPS_API.QuestList`), each at its point on the ground (`x = gx * TILE`, `y = -gy * TILE`, height from `GroundHeight`, kept with the quest), projected with `Project` in `Render` (`ns.UpdateQuestPins`, a layer at canvas level + `BUCKET_FRAMES` + 5, over the ground, your arrow and the models), hidden off the view; their objective areas are not drawn yet: the game's area frame is flat and cannot be bent into perspective, and the planned way (asking it which quest's area is at each point of a grid, then drawing those cells on the ground) waits on the in-game check (`/gps test`, `quests: 3.`).
  - The game's own models (`Models.lua`, since 2026-10-17): props and trees (M2 doodads) and buildings (WMOs) as the game's real models, actors in the same ModelScene as your character (same camera). Data: `Data/Models_<map>.lua` (16 maps, 415,011 placements of 9,441 models, 8.0 MB; since 2026-10-18 the 382 caves and mines are in again as kind 2, their own model entries (196), and are drawn like the other buildings when the game loads WMOs (`/gps3d models caves on|off`, `GPS3D_DB.caves`, default on): only the cave's own rock hides its tunnels, since the terrain is not in the scene's depth buffer, so if tunnels show through the ground in the game, `caves off` leaves them out and their outside parts stay as the simplified shapes; with the game's buildings refused they are the simplified shapes anyway; generated by `scripts/browser_export_models.js` (or `scripts/export_models_node.ts`, the same script on MapExplorer's reader in Node) + `scripts/build_models.py`, from game build 1.60.1.70450): per map `ns.ModelFiles[map]` (FileDataID, kind, radius across the ground, lowest and highest point, model units) and per tile `ns.Models[map][ty * 64 + tx]` (19 base64 characters per placement: model, x, y, height, yaw, pitch, roll, scale; biggest first). Rotation in GPS3D's axes as yaw (about up, from east toward north), pitch, roll applied Rz Ry Rx, which is the actor's `SetYaw`/`SetPitch`/`SetRoll` (read back from MapExplorer's placement matrices, worst error 2e-7 over every placement). Tiles are decoded when first needed (200 kept); each map's buildings are in one list (`WmoList`), so a big one whose middle is far off is still found. Which ones (`Select`, on a driver frame's OnUpdate, at most every 0.1 s and only when the view has moved more than 4 % of the distance, zoomed 5 %, turned or tilted 2 degrees, or the window was resized; `ns.UpdateModels` from `Render` only notes that): within *Model distance* of the middle of the view (buildings: their radius further), in view, at least *Smallest model* pixels on screen; every building that passes, then props biggest on screen first up to *Props and trees at most*; tilted (under 80 degrees), props whose line to the camera passes under the ground (6 samples of the grid) are left out. Actors are pooled (at most 3,000) and keep their model: a model still chosen keeps its actor, one showing the same model is reused before another has to load (`SetModelByFileID`), at most 40 loads per choice (the rest follow). A model not loaded after 10 s counts as failed and is not chosen again. Buildings: whether the game draws a WMO in an addon's ModelScene is checked once per game build (`GPS3D_DB.wmoCheck`, `wmoBuild`): the first WMO actor that reports loaded with a real bounding box (`GetActiveBoundingBox`) says yes, none within 8 s (or `SetModelByFileID` refusing them) says no, said once in chat and in the debug log; while it runs and when the answer is no, the simplified building blocks stay; with yes, the blocks wholly within *Model distance* of the middle of the last choice give way (`ns.ModelsCover`, called from the block loop), except blocks under the footprint of a building that is not drawn (still loading, or one that never loads), and further out the simplified blocks stay. Stormwind City is one building model in Forever (FileDataID 7962574, radius 853 yd) whose lamps, trees and benches are part of it (its doodad sets), not map doodads, so the city has few props of its own: with the game's buildings refused there are only the simplified shapes and a few dozen props. Rolling the models back: `notes/rollback-before-game-models/` (the two GPS3D files from before, and ROLLBACK.md; switching *Buildings close up* to simplified and *Props and trees* off draws exactly what the view drew before, checked by `test_models.py`). `/gps3d models` (state), `buildings game|simple`, `props on|off`, `count`, `range`, `px`, `wmo` (check again), `turn <deg>` and `tilt normal|flip|off` (fixes for the in-game check, if every model faces or leans the wrong way). ## Coordinates

The 64x64 ADT grid: tile (x, y) covers [x, x+1] x [y, y+1], x east, y south, 533 1/3 yards per tile. World X (north) and Y (west) map to it as `gx = 32 - Y / 533.33`, `gy = 32 - X / 533.33`. `UnitPosition("player")` returns X first, then Y, then Z and the map (instance) ID, which is the key into `ns.Maps`.

## Regenerating the data

1. Open https://coldensjo.github.io/ClassicWowMapExplorer/, choose `C:\Program Files (x86)\World of Warcraft`, game version Forever.
2. Paste `scripts/browser_export.js` into the page's console, move the camera once, then run `await gpsExport()`; it downloads `gps-export.zip`.
3. `python scripts/build_maptiles.py path/to/gps-export.zip`.

## API compatibility (checked 2026-10-13)

Every function, widget method, template and font the two addons use was checked against Forever's own UI source (Blizzard's `forever` branch, build 1.60.1.70338, via Gethe/wow-ui-source): all exist. Secret-value rules (Forever carries Midnight's addon restrictions): none of the values read (UnitPosition, GetPlayerFacing, C_Map positions, our own frames' size, position and scale) are marked as secret returns for frames like ours; the code still checks `issecretvalue` and treats hidden values as "position not available". The 8-argument `SetTexCoord` used for 3D triangles is the form Blizzard's Forever code uses (corners in the order upper-left, lower-left, upper-right, lower-right). `Bindings.xml` uses the `category="BINDING_HEADER_..."` form Blizzard's Forever bindings use. ## Tech

Lua 5.1 (WoW), private namespace `local addonName, ns = ...`, no globals except `GPS_MapFrame`, `GPS_WorldMapFrame`, `GPS_DebugFrame`, `GPS_Toggle`, `GPS_API`, the saved variables `GnomishPositioningSystemDB` and `GnomishPositioningSystemLog`, the slash command and the binding strings (GPS3D: `GPS3D_Frame`, `GPS3D_API`, `GPS3D_DB`, `/gps3d`). Python 3 + Pillow for the converter. `GPS3D.lua` is close to two Lua 5.1 limits the sandbox's Lua 5.4 does not catch: 200 local variables alive at once in the main chunk (197) and 60 upvalues in a function (`RenderWorld`, the frame's drawing, uses 58). Put new helpers in `do` blocks or on tables (`ns`), and run `tools/sandbox/test_luac.py`: it compiles every shipped file, data included, with `luac5.1` and prints both numbers for each code file.
