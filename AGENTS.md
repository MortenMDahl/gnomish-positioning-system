# AI Agent Handoff: Gnomish Positioning System (GPS)

GPS is a World of Warcraft addon for **WoW Forever** that replaces the cartoon world map with a zoomable top-down map built from the game's own minimap images. A 3D (perspective) mode is being prototyped separately, and Blizzard's own map ("the traditional map") is the third mode, the one that opens where GPS cannot show you. The design, measurements and decisions are in `INTEGRATION_PLAN.md`; read it before changing anything.

## Layout

- `Interface/AddOns/GnomishPositioningSystem/`: the addon (about 3 MB).
  - `Debug.lua` (since 2026-10-17, loaded first): the debug log, `/gps debug on|off|clear|show|mark <note>` and a switch on the settings page. Off by default, and then `ns.Log(category, format, ...)` returns at once (measured: no change in 2D or 3D frame times). On, lines (`HH:MM:SS  GetTime  CATEGORY  text`) go to the saved variable `GnomishPositioningSystemLog` (`{ on, lines, bytes }`), which the game writes on `/reload`, logout or quitting to `WTF\Account\<account>\SavedVariables\GnomishPositioningSystem.lua`: the file to hand over (addons cannot write other files). Size: at most 1,000,000 bytes of text (about 10,000 lines); past that the oldest lines are dropped to 800,000 bytes, with a note; one line at most 400 characters; at each login with the log on, a chat reminder says so. Categories: COMPAT (other addons' map layers found, copied, left alone, switched off, removed; GatherMate2's node list), MODELS (GPS3D's game models: the building check's answer, models that never load), SESSION (header at login/reload and when turned on: build, versions, screen and scale, data and APIs, quests and zones known, both settings tables, your position), SLASH, MODE, WINDOW, VIEW (each window's view when it changes; the 3D one from `GPS3D_API.DebugState`), MAP, MAPWIN, QUEST, SETTING, POS (your position when you move more than 2 yd or turn, else every 10 s; checked every second), PERF (2D layout times, 3D frame times from `GPS3D_API.TakePerf`, game fps; every 5 s), MEMORY (every 30 s), EVENT (loading screens, zones, combat, UI scale, logout), TAINT (`ADDON_ACTION_BLOCKED` / `FORBIDDEN`), ERROR (every Lua error whose text or stack mentions GPS's files, one line per line of message and stack; the hook is `seterrorhandler`, installed only while on and given back when turned off, and the game's own handler still runs), MARK (your notes), TEST (the self-test lines). GPS3D logs through `GPS_API.Log` (camera mode, straight down, view map, Me failures, slash commands, self-test). `/gps debug show` opens the newest 1,500 lines in a window to copy (Ctrl+A, Ctrl+C).

Modes (since 2026-10-17): the 2D map, the 3D view (GPS3D) and the traditional map (`MapWindow.lua`), one window at a time at the same place and size. `ns.modes[name]` says how to open each (`Frame`, `open(from, focus)`, `focus()`, `available()`); the mode ring (`ui.modeSwitch`, labelled `2D` / `3D` or a folded-map icon) steps 2D -> 3D -> Map -> 2D, right-click steps back (`ns.StepMode`), and the mode picked is remembered (`db.mode`). `GPS_Toggle` (the key binding, `/gps`) closes whichever window is open, or opens `ns.DefaultMode()`: the remembered mode, except the traditional map where GPS cannot show you (`ns.PlayerOnGPSMap()` false: no `UnitPosition`, or a map GPS has no data for). `ns.CheckAutoMode` (PLAYER_ENTERING_WORLD, ZONE_CHANGED_NEW_AREA, and again 1 s later) switches a 2D or 3D window that is showing you to the traditional map when that changes to false, and back when it changes to true if the switch was automatic (`ns.autoMap`); a mode picked by hand stays until the next such change. Focus passed between modes: `{ map, gx, gy }`, `"you"` (the window left was showing you: follow you), or nil (open as last time). `/gps 2d`, `/gps 3d`, `/gps map` open a mode by name (`ns.OpenNamed`; GPS3D's `/gps3d` commands use it too, through `GPS3D_API.Open`, so only one window is ever open). Full screen (since 2026-10-21, `ns.SetFullScreen`, `db.fullScreen`, `/gps fullscreen`): the button left of the close X (Blizzard's maximize art, `RedButton-Expand` / `RedButton-Condense`, from `MaximizeMinimizeButtonFrameTemplate` in Forever's `SharedUIPanelTemplates.xml`) anchors the window to UIParent's corners in every mode (`ns.CopyGeometry` does the same while it is on), hides the resize grip, stops the band's drag, and leaves the saved place and size untouched (`ns.SaveFrame` returns at once), so turning it off goes back to exactly them; restored at login; `/gps reset` turns it off. At most 400 hit-tests and 2 ms a frame (in the sandbox one area is about 1,700 hit-tests over 5 frames); redone after the quest log changes, the old shape drawn until then. Which way the hit-test answers is unknown from the source, so three are tried in turn and the one that finds an area kept: the frame hidden, shown at alpha 0, shown behind the 3D view's ground (in its window under its opaque background, `GPS_API.SetQuestAreaHost`); with no frame or no hit-test nothing is drawn (`Q.area.broken`). `GPS_API.QuestAreaStatus` is the `/gps3d test` line; QUEST debug lines say how each area was found. - `prototypes/GPS3D/`: the 3D view (`/gps3d`, depends on GPS, saves `GPS3D_DB`).
  - Terrain for the whole game: `Data/World_<map>.lua` (16 maps with outdoor terrain, 2,277 tiles, 4.8 MB; generated by `scripts/build_world.py`): per ADT tile a 33x33 height grid (16.7 yd apart; ground, liquid surface or sea level, whichever is highest), 2 base64 characters per height. Since 2026-10-17 each string ends with 2 more characters, the tile's highest height (`build_world.py`), and heights are read from the strings when needed (`TileHeights` returns `{ s, base, lo, hi }` with the heights behind `__index`): nothing is decoded ahead or kept, where before every tile in view was decoded into a table for its height range and kept (a first zoom-out over a continent cost 90-160 ms in one frame and 20-30 MB that stayed; now about 20 ms and under 3 MB in the sandbox). Tiles around the camera become triangles within a triangle budget (3,200 by default, `/gps3d budget`), tiles outside the view skipped. Since 2026-10-22 (J8, `Terrain.lua`, `Data/Lod_<map>.lua`, `tools/sandbox/test_terrain.py`) each tile is an uneven mesh: a right-triangle bintree whose points join in the order of the height error they take off, worked out offline (`scripts/build_terrain_lod.py`, with `scripts/terrain_lod.py`; every string decoded again and checked; 1,503 tiles, the 774 flat ones drawn as the even bintree; 1.46 MB in 16 files, +1.5 MB Lua memory and 7 ms to load in Lua 5.1), at eleven nested levels from 2,048 triangles to 2, so a cliff keeps many triangles at a level where a flat field has few (levels 1 and 3, 1,024 and 256 triangles, are not drawn: zooming in, a tile is made again at every level it passes, and with them the straight-down zooms took 12-21 % longer than with the even grids). At the far views, at the triangle count of the even grids of 2026-10-21, the height error on screen is 6-21 % lower (Mount Hyjal 5,000 yd tilted 6 %, Stormwind 3,000 yd tilted 16 %, Durotar 4,000 yd straight down 21 %, Thousand Needles 14 %, Stranglethorn 20 %; offline, with the best possible share of those triangles, 11-15 % for this mesh and 16-26 % for a free mesh per tile, which cannot be nested: `scripts/terrain_lod_study.py`), at the same frame time (sandbox: zoom sweeps -10 to +1 %, far views -20 to +4 %); a third less error at Mount Hyjal would take about twice the triangles there and a quarter more frame time. The choice (since 2026-10-21, J1): each tile's level from its own errors (the mean height error of each level against the full grid, stored with it) per triangle saved, against its distance squared, and the texture's linear-mapping error against the distance cubed (none for open sea, drawn in one colour), so the triangles go where they take most error off the screen; the count is 1.3 x what the rule before 2026-10-21 (cells about 26 px on screen) drew on the tiles in view. `ChooseTiles` skips tiles out of view before their eight-corner test (since 2026-10-22 first by blocks of 4 x 4 tiles, `Lod.Blocks`: zoomed out over Mount Hyjal about 900 tiles are in range and 240 in view) and does not draw the ground of tiles wholly beside the view (they stay candidates for building blocks). Points a coarser level drops are drawn part way to the middle of their two parents by the tile's distance (geomorphing), fully there before the tile switches, so changing level moves nothing: zooming in at 2 % a frame the ground at a fixed point moved up to 160 px in one frame before 2026-10-21, up to 14 px with the even grids, at most 6 px now, 99 % of the time under 0.7 px. Tile edges use the smaller threshold of the two tiles, so no cracks without matching edges by hand, and shared edges and corners take one height for both tiles (50 of 4,243 shared edges in the data differ, by up to 301 yd, cracks before 2026-10-21). `GridHeight` splits each cell along the diagonal the full bintree has there (alternating). ## Coordinates

The 64x64 ADT grid: tile (x, y) covers [x, x+1] x [y, y+1], x east, y south, 533 1/3 yards per tile. World X (north) and Y (west) map to it as `gx = 32 - Y / 533.33`, `gy = 32 - X / 533.33`. `UnitPosition("player")` returns X first, then Y, then Z and the map (instance) ID, which is the key into `ns.Maps`.

## Regenerating the data

1. Open https://coldensjo.github.io/ClassicWowMapExplorer/, choose `C:\Program Files (x86)\World of Warcraft`, game version Forever.
2. Paste `scripts/browser_export.js` into the page's console, move the camera once, then run `await gpsExport()`; it downloads `gps-export.zip`.
3. `python scripts/build_maptiles.py path/to/gps-export.zip`.

## API compatibility (checked 2026-10-13)

Every function, widget method, template and font the two addons use was checked against Forever's own UI source (Blizzard's `forever` branch, build 1.60.1.70338, via Gethe/wow-ui-source): all exist. Secret-value rules (Forever carries Midnight's addon restrictions): none of the values read (UnitPosition, GetPlayerFacing, C_Map positions, our own frames' size, position and scale) are marked as secret returns for frames like ours; the code still checks `issecretvalue` and treats hidden values as "position not available". The 8-argument `SetTexCoord` used for 3D triangles is the form Blizzard's Forever code uses (corners in the order upper-left, lower-left, upper-right, lower-right). `Bindings.xml` uses the `category="BINDING_HEADER_..."` form Blizzard's Forever bindings use. The look and the 3D marker added (checked against the same build): `BackdropTemplate` with `SetBackdrop`/`SetBackdropColor`/`SetBackdropBorderColor`, `CreateColor`, `Texture:SetGradient(orientation, minColor, maxColor)`, `FontString:SetWordWrap`/`GetStringWidth`, the fonts `GameFontNormalLarge`, `GameFontHighlight`, `GameFontHighlightSmall`, `GameFontNormalSmall`, `GameTooltip_Hide`, and the ModelScene actor's `SetModelByUnit` (marked `RequiresDeclassifiedUnitIdentity`; fine for "player" as far as the source says, the self-test reports it). `UnitPosition` documents a real `positionZ` return, used for your height. Not answerable from the source, so covered by the self-tests: whether addons may load minimap images by FileDataID, and whether JPEG loads from an addon folder.

## Tech

Lua 5.1 (WoW), private namespace `local addonName, ns = ...`, no globals except `GPS_MapFrame`, `GPS_WorldMapFrame`, `GPS_DebugFrame`, `GPS_Toggle`, `GPS_API`, the saved variables `GnomishPositioningSystemDB` and `GnomishPositioningSystemLog`, the slash command and the binding strings (GPS3D: `GPS3D_Frame`, `GPS3D_API`, `GPS3D_DB`, `/gps3d`). Python 3 + Pillow for the converter. `GPS3D.lua` is close to two Lua 5.1 limits the sandbox's Lua 5.4 does not catch: 200 local variables alive at once in the main chunk (195) and 60 upvalues in a function (45 at most since 2026-10-22, when the ground's level of detail moved to `Terrain.lua`; `RenderWorld`, the frame's drawing, used 58). Put new helpers in `do` blocks or on tables (`ns`), and run `tools/sandbox/test_luac.py`: it compiles every shipped file, data included, with `luac5.1` and prints both numbers for each code file.
